AI tiers: free, paid and self-serve¶

Status, 2026-11-18: built on branch agent/ai-tiers (PR #548), with the owner’s decisions applied (last section). The free tier and the model-setup sheet work. The paid tier is a placeholder that turns on when ai-billing (branch agent/ai-billing, docs/design/ai-billing.md) lands. Not yet tried for real: the OAuth redirect with a real OpenRouter login (tested against a mock only), and the iOS one-tap sign-in in a real app build (needs the App Store build below; the Swift can’t be compiled in the container).

What the user sees¶

The first time someone sends an AI prompt with nothing set up (in the effect editor, or via “Set up AI” in the effects library), a Set up AI sheet opens. It holds on to the prompt and sends it once setup is done. The same sheet opens from Settings ▸ AI ▸ Model setup… at any time. Users who already have a key, endpoint or on-device model configured never see it.

  • Free: pick a model, then tap Connect OpenRouter (free). This runs OpenRouter’s OAuth PKCE flow, which gives the user their own key. Fallback: “I have an OpenRouter key” (paste a key; it is checked with GET /api/v1/key).

  • Paid: the card shows “Coming soon” until both conditions below hold, then selects the credits provider (see the seam section).

  • Bring your own: paste an Anthropic key directly in the sheet, or go to Settings ▸ AI for an OpenAI-compatible endpoint, an on-device model (CPU or WebGPU) or another cloud vendor. These options already existed; nothing new was added there. The OpenAI-compatible endpoint covers paid OpenRouter, Ollama, LM Studio and the llama.cpp server. It is now tested against a fake local server.

  • When the free daily limit is used up, the editor says so (“You’ve used today’s free OpenRouter requests (50 per day). It resets at HH:MM…”), suggests the other tiers, and shows a Model setup… button. A revoked key shows the same button.

Screenshots (mocked OpenRouter, all other network blocked) are in /workspace/.claude/aitiers/status/, which is not committed.

Flows¶

PWA / browser (redirect). beginOAuth creates a code_verifier and stores the verifier, the state, the route to return to and the chosen model in localStorage. It then navigates to openrouter.ai/auth?callback_url=<origin+path>&code_challenge=…&code_challenge_method=S256&state=…. OpenRouter sends the user back with ?code&state. At boot, before the router starts, finishOpenRouterRedirect checks that the state matches and calls POST /api/v1/auth/keys {code, code_verifier, code_challenge_method} to get {key}. It then stores the key under the free tier, strips the code from the URL and restores the route. When the editor mounts, it takes the pending prompt for that route and sends it.

localStorage is used rather than sessionStorage because an installed Android PWA can come back in a browser tab. If the sheet is open in another tab, a storage event lets it pick up the new config.

iOS app (one tap). The Capacitor WKWebView opens off-origin pages in Safari, and nothing brings a redirect back into the app by itself. So the app ships a small first-party plugin, @splanc/web-auth (web/native-plugins/web-auth), that runs an ASWebAuthenticationSession: the system sign-in sheet. It shares Safari’s cookies, so a user already signed in to OpenRouter just taps Authorize.

  1. beginOAuth({mode: "native"}) stores the PKCE record and builds the authorize URL with callback_url=https://splanc.io/app/oauth-callback.html. OpenRouter needs an https callback.

  2. That bounce page (web/public/oauth-callback.html, deployed with the web app) forwards only code / state / error to splanc://oauth/openrouter.

  3. The session watches for the splanc scheme, captures that URL itself, and returns it to JS. No URL type or entitlement is registered, so another app claiming splanc:// can’t intercept it. The PKCE verifier never leaves the app, so a leaked code is useless.

  4. completeOAuthNative requires the state to match, then exchanges the code. Closing the sheet is a quiet cancel.

If the plugin is missing or the sheet fails, the app falls back to OpenRouter’s headless mode: no callback_url, OpenRouter shows a one-time code (valid 10 minutes) to paste into the sheet (“Sign in with a code instead”).

CORS. openrouter.ai/api/v1/* answers Access-Control-Allow-Origin: * for both https:// and capacitor://localhost, so the app can call it directly. Checked with a live preflight.

There is no Splanc server and no shared key in the free tier.

Shared demo relay (Acid Mode / kiosk / website playground)¶

With no AI set up, Acid Mode, the kiosk and the website playground keep using the zero-setup shared relay (web/_worker.js, /api/demo-ai/chat/completions on the Cloudflare Pages project; key server-side only). Since this PR it behaves like the free tier:

  • Models: Nemotron 3.5 Lightning, then Nemotron 3 Ultra, then Nemotron 3.5 Super. That is the same order as the app’s FREE_MODELS minus the private pick, and a unit test keeps the two lists equal. A request carrying an image goes only to the vision model.

  • Settings: reasoning off and every attempt zero-priced. The paid Claude models that led since 2026-10-30 are gone.

  • System prompt: the client’s, passed through unchanged. Both paths build it with the same runChatTurn / CHAT_SYSTEM / Acid persona. The relay only still rewrites the legacy Acid play persona that old app builds send.

  • Limits: per isolate 20/min, 8 in flight. Per client (IPv4 or IPv6 /64): 6/min, 2 in flight, and 30/hour. The hourly share is back to 30 from 60, since the shared 1000/day free cap binds again. Optional AI_RATE_LIMITER binding adds edge enforcement.

  • Secret: OPENROUTER_API_KEY on the Pages project. It is the existing name and needs no change. Use a key whose account has bought ≥ $10 of credits (1000 free requests/day); the relay can no longer spend them. Optional: DEMO_DEV_ORIGIN.

Checked with the relay code (not deployed) against the live API (/workspace/.claude/aitiers/eval/relay_live.json): an editor request with the app’s CHAT_SYSTEM was answered by Lightning in 2.0 s with a set_script call; a request with a preview image went to Nemotron 3.5 Super in 2.9 s.

Provider¶

web/src/effects/ai/providers/openrouter.ts now serves the cloud vendor openrouter for both the free tier and paid OpenRouter keys. It:

  • streams responses, rebuilding tool calls from their deltas, and shows the set_script summary as the status;

  • sends reasoning: {enabled: false} for free models. With its default reasoning, Nemotron 3.5 Super spent all 4000 output tokens on reasoning and never made a tool call;

  • sends a models list for fallback that contains only :free models;

  • sends provider.data_collection: "deny" for models marked private;

  • returns typed errors: daily_limit, rate_limited (per minute), upstream_busy, auth, payment, model_unavailable (including the privacy-settings block), and unavailable.

Browsers cannot read Retry-After or X-RateLimit-*, because OpenRouter does not list them in its CORS exposed headers. Reset times therefore come from error.metadata.headers in the response body.

Checked against the live API (/workspace/.claude/aitiers/eval/live_check.json):

  • The default model returned a set_script call in 1.2 s, with the summary streamed as the status.

  • A bad key produced the auth error.

  • An unknown model id produced model_unavailable.

  • GET /key returned the daily free allowance.

Model choice (eval)¶

Tool: tools/fx_agent_eval/openrouter_eval.py. It uses the app’s real CHAT_SYSTEM prompt and its set_script tool (rendered from the tree), the 15 fixed prompts in prompts.json, the host fx_compile, and allows up to 2 repair rounds with the compiler’s diagnostics returned as the tool result.

The run was against the live API on 2026-11-18 with the owner’s key, free models only, with requests spaced 3.5 s apart. 125 of the key’s 1000 daily free requests were used. Raw results are in tools/fx_agent_eval/out/openrouter/.

The picker offers these, in order:

  1. Nemotron 3.5 Lightning (default)

  2. Nemotron 3 Ultra

  3. Nemotron 3.5 Super

  4. Cohere North Mini Code, labelled “Not used for training”

The picker also accepts any other :free id.

For comparison, Claude on the same 15 prompts (the app2 rows in tools/fx_agent_eval/out/summary.md) compiles 15/15. That run used a different harness: claude -p returning a code block, not a tool call.

Caveats:

  • Compiling is not the same as looking right. No judge pass was run on these outputs.

  • n=15 per model, single run.

  • The free catalog changes often (the MiniMax model shortlisted in October is gone). Rerun with OPENROUTER_KEY_FILE=… python3 openrouter_eval.py --fx-compile <fx_compile>.

Models without tool calling are not offered. If a user types such an id anyway, the existing loop falls back to plain chat with no tools.

Vision (capture_preview) on the free tier is on only for accounts with the 1000/day allowance, because each capture is one more request.

  • The limit comes from GET /api/v1/key (free_model_daily_requests.limit). It is read at connect time, at boot when the cached value is older than 6 h, and whenever Settings ▸ AI shows the allowance. A 429 that names the daily limit also updates it.

  • Lightning, the default, is text-only. A turn that carries a preview image is sent to the curated free vision models (Nemotron 3.5 Super) instead.

  • Never for the private (Cohere) pick.

Privacy¶

Free variants on OpenRouter are mostly served by endpoints that may keep and train on prompts. A request with data_collection: "deny" for the Nemotron models returns 404 “No endpoints found matching your data policy (Free model training)”. The OpenRouter account must also allow “Free model training” in its privacy settings, or those models return the same 404. The app’s error message says this. Cohere North Mini Code and Ling do route with “deny”, so the private choice enforces it on every request.

Chat content goes from the user’s device to OpenRouter under the user’s own account. Splanc never sees it.

Paid-tier seam (with agent/ai-billing)¶

This PR does not import the credits provider. It assumes only these four things, matching providers/credits.ts on agent/ai-billing:

  • The flag is localStorage["splanc.flags.aiCredits"] === "1".

  • Selecting the tier means updateAiConfig({kind: "credits"}).

  • Before the billing PR merges, normalizeConfig drops the unknown kind. The card checks this with the pure function paidTierSupported() and stays “Coming soon”.

  • Buying credits is its own flow (#/credits, ai-billing.md); the account lives in Settings ▸ AI. When credits are selected but no session exists, the sheet opens that flow and keeps the prompt.

A three-way merge of both branches’ edits to generate.ts, aiSettings.ts, provider.ts and anthropic.ts has no conflicts.

Owner decisions (2026-11-18)¶

  1. Default free model: Nemotron 3.5 Lightning.

  2. iOS one tap: built (WebAuth plugin + bounce page, above).

  3. Acid Mode / kiosk: stays on the zero-setup shared relay, now on the free tier’s models and prompt (above). The owner deploys after merge.

  4. Free-tier vision: on only at 1000/day (above).

  5. Attribution headers: kept (HTTP-Referer: https://splanc.io, X-Title: Splanc).

Shipping the iOS one-tap build¶

Nothing new in Info.plist or entitlements: ASWebAuthenticationSession needs neither, and the plugin is picked up by cap sync like the other first-party bridges.

  1. Merge, then deploy the web app first, so https://splanc.io/app/oauth-callback.html is live before any app build uses it. Check that it loads and redirects to splanc://oauth/openrouter?....

  2. Deploy the Pages worker (relay change) when convenient. It is independent of the app build.

  3. On the Mac, run pnpm install from the repo root. This links @splanc/web-auth, a new link: dependency of web/.

  4. Run bazel run //tools:ios_testflight (or the macOS workflow’s TestFlight job). Its cap-sync step adds SplancWebAuth to the CapApp-SPM package graph, then archives and uploads. For a quick device check first: tools/iosctl rebuild and tools/iosctl launch --target <UDID>.

  5. TestFlight check:

    • Settings ▸ AI ▸ Model setup… ▸ Free ▸ Connect OpenRouter. The system sheet (“Splanc wants to use openrouter.ai to sign in”) appears.

    • Sign in and Authorize. The sheet closes and the free tier is ready.

    • Send a prompt.

    • Repeat while already signed in to OpenRouter in Safari: it should be one tap.

    • Cancel the sheet: no error.

  6. App Review notes: AI sign-in uses the standard system sign-in sheet for the user’s own OpenRouter account. The free tier needs no purchase, and the paid tier stays behind its flag.
