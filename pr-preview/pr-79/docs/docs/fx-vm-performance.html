FX-VM performance¶

Measured FX-VM performance across hardware platforms, fitted from the golden HITL benchmark bundles (web/tests/testdata/device-bench-*.json) captured on real devices over the rig. This file is auto-generated and pinned by CI — regenerate it with:

bazel run //web:gen_fx_vm_perf_doc

The numbers come from the same cost model the app and CI use: buildDeviceProfile (web/src/effects/deviceProfile.ts) fits the per-opcode table and validates it against held-out programs (profileValidation.ts), gated at the same tolerance as web/tests/deviceProfileHardware.test.ts. See docs/design/perf-monitoring.md for the methodology and EFFECTS.md for the narrative.

Builtin costs (effects-AI ranking)¶

Rendered verbatim from builtinCostsToPrompt — the per-builtin ranking the in-editor AI is fed, relative to a float multiply (each runs once per LED in shade()):

BUILTIN COSTS on this device (esp32c6 @ 160 MHz, measured on your board) — per call, relative to a float multiply. shade() runs each ONCE PER LED, so favor the cheap ones:
  abs 0.5x, sign 0.6x, hash 0.7x, dot 0.8x, max 0.9x, min 0.9x, step 1.0x, floor 1.0x, sub 1.0x, add 1.0x, mul 1.0x, clamp 1.2x, length 1.2x, fract 1.2x, mix 1.4x, div 1.5x, ceil 1.5x, distance 1.7x, normalize 1.8x, sin 2.0x, palette0 2.1x, cos 2.2x, mod 2.3x, sqrt 2.4x, smoothstep 2.7x, log 2.8x, exp 2.9x, cross 3.3x, atan2 3.7x, tan 4.4x, hsv2rgb 4.5x, pow 6.2x
Hoist the pricey builtins (pow/atan2/log/exp/length/normalize/distance/smoothstep) out of shade() into update() or precompute into state; swap sin/cos/pow for fixed16/fixed8 (LUT trig, no soft-float) or step/mix/polynomials; avoid length/normalize where a squared distance works (hidden sqrt).
