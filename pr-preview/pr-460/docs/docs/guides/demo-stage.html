Run a demo night with the Splanc stage¶

splanc-agent stage turns a laptop and a TV into a live demo: you speak a request, Claude writes an effect, and the audience watches it happen. The stage page shows the code as it is being written, every step (compile, preview, deploy), Claude’s reply in large type (and spoken aloud), a live preview of two fixtures on their real maps, and, next to all that, your phone’s screen (mirrored), so the audience can follow the app while you map a fixture or play with effects. Ask Claude how something works and it explains the code on screen, highlighting and labelling each part as it talks.

 ┌──────────┬──────────────────────────┬────────────────────┐
 │          │ Effect: Pumpkin glow     │ "make the pumpkins │
 │  your    │  uniform float warmth …  │  breathe slowly"   │
 │  phone   │  vec3 shade(Led led) {   │ Breathing orange…  │
 │ (mirror) │  …                       │ ● Compile   41 ms  │
 │          ├──────────────────────────┴────────────────────┤
 │          │ Live preview  [SpookySplanc1] [SpookySplanc2] │
 └──────────┴───────────────────────────────────────────────┘

What you need¶

  • A Mac on the same Wi-Fi as the fixtures, with Chrome or Safari (for speech recognition).

  • A TV on HDMI, set up as an extended display.

  • An iPhone with the Splanc app and a USB cable (for the mirror). Mirroring over AirPlay works too, but a cable doesn’t drop out on busy venue Wi-Fi.

  • A Claude API key: create one at console.anthropic.com → API keys. Each spoken request costs roughly 5–15¢ (Claude Opus 5.5). Give the key a spend limit for the night.

  • Optional: a microphone (a USB or lapel mic beats the laptop’s own), and a presenter clicker.

Start it¶

export ANTHROPIC_API_KEY=sk-ant-…          # or: --api-key-file ~/claude.key
npx -y https://splanc.io/agent/splanc-agent.tgz stage

It finds the fixtures the same way the MCP server does, then opens the stage page (http://localhost:7420/). Drag that window to the TV and make it full screen (Chrome: Ctrl+Cmd+F). Each fixture with a stored map appears in the live-preview strip right away, dimmed, until an effect runs on it.

Options: --port 7420; --effort low for quicker, simpler replies (default medium); --lan also serves the page to other devices on the network, behind a key printed at start (the microphone works only on the laptop itself); --no-open doesn’t open the browser.

Put the phone on screen¶

Android (ScreenStream). The phone slot shows ScreenStream’s page in a frame:

  1. Use the ScreenStream fork (github.com/fughilli/ScreenStream, which allows a page on the laptop itself to frame it). Start it on the phone; the phone and the laptop must be on the same network.

  2. On the stage, click Phone. A QR code appears; scan it with the phone’s camera.

  3. The page that opens on the phone has the phone’s ScreenStream address filled in (https://<phone>:8081/; for stock ScreenStream tap the http://…:8080/ link). Tap Show on the TV. The phone’s screen appears in the slot.

  4. There’s no certificate warning to accept: the stage connects to the phone itself and shows its page from localhost. It pins the certificate the phone presents when paired (Phone shows its SHA-256; ScreenStream shows the same one), and refuses a different one until you pair again.

  5. Press F to show the phone large across the stage (the header stays in view); F or Esc puts it back in its slot.

  6. Type ScreenStream’s PIN into the slot if it asks. Then click anywhere on the stage outside the slot before pressing Space or F: keys typed into the slot go to the phone’s page.

Click Phone again (or Hide it from the TV on the phone) to take it off screen. The QR code works for the whole session; if the laptop has several network addresses (VPN, two Wi-Fi), the others are listed under the code: click one to switch the code to it. Pairing uses the stage’s port

  • 1 (7421) on the local network.

iPhone (QuickTime), or any window. Plug the iPhone into the Mac and unlock it. Open QuickTime Player → File → New Movie Recording, and pick the iPhone as the camera next to the record button. Then click Phone ▸ Capture a window instead and pick the QuickTime window. Keep that window on the laptop screen, not the TV (behind other windows is fine).

Talk to it¶

Do this

To

Hold Space, speak, release

send a request (what you say appears as you speak)

Clicker Page Down / Page Up (or B)

start listening, then press again to send

Enter

type a request instead

V

turn Claude’s voice on or off

F

show the phone large (again, or Esc, to shrink it)

G

show or hide the preview’s ground grid and axes

Esc

stop Claude’s request (and its voice)

New

start a fresh conversation

Maps

re-read the fixtures’ maps (after mapping one in the app)

Things that demo well:

  • “Make the curtain look like a slow ocean wave, deep blue and teal.”

  • “Faster.” / “Warmer.” / “Calmer.” Claude turns the running effect’s knobs instead of writing a new one.

  • “Now fade both fixtures to a flickering candle.” Claude crossfades both in sync.

  • “Go back.” Claude rolls back to the previous effect.

  • “Show me the rope’s map.” Claude plots the fixture.

  • “How does that work?” / “What does the speed knob do?” Claude explains the code (below).

  • “Show me the wreath.” Claude brings that fixture into the live preview (below).

The conversation carries on between requests, so follow-ups like “same, but purple” work.

Each request gets a number, and the badge on the Conversation panel says where the latest one is: queued, thinking, writing code, running a tool, deploying, done, failed, stopped or superseded. One request runs at a time and the newest wins: asking again while Claude is still busy replaces the request in flight (like talking over the voice), and Esc stops it. A replaced or stopped request makes no further tool calls, its call in flight is cancelled, and whatever it would still have sent to a fixture is dropped, so an old effect can’t turn up on the lights later. Claude is told the earlier request was cut off. The stage asks for no approvals: it can only use the tools listed below.

The page can be reloaded, or opened on a second screen, at any time: it redraws the current conversation, its tool calls and the code from the stage’s history.

On stage Claude can only use the effect and look tools. It can’t rename fixtures, update firmware, change Wi-Fi, delete saved looks or re-trust certificates, whatever it hears.

Claude explains its code¶

Ask a question about an effect (“how does the breathing work?”, “why is it so smooth?”, “what does line 12 do?”) and Claude teaches from the code panel. It talks through the code a step at a time; as each sentence starts, the part it’s about is highlighted, boxed or underlined, gets a short comic-style label, and scrolls into view. To explain a different effect, name it (“explain the candle effect from the library”) and Claude opens it in the code panel first. Questions don’t change the lights unless you ask for that too.

Claude’s replies are spoken aloud by Kokoro, an open-weights neural voice that runs in the browser itself (no key, no cost). The words light up as they are spoken. The first time, the page downloads the voice model (about 90 MB, from Hugging Face) and the browser keeps it, so load the page once on the night’s network before the show. Until the model is ready, and on browsers that can’t run it, the system voice speaks instead. Chrome on a Mac runs it on the GPU (WebGPU); without that it runs on the CPU and the first words take longer.

Press V (or the Voice button) to turn the voice off; walkthroughs then step along at reading pace. Pressing Space to talk cuts the voice off. Options in the page address:

  • ?voice=af_bella picks a Kokoro voice: af_heart (default), af_bella, am_michael, bf_emma, bm_george and others (samples on the model card).

  • &rate=1.1 speeds it up (1 is normal).

  • ?tts=system uses the computer’s own voice instead; then ?voice= takes part of a system voice’s name (e.g. ?tts=system&voice=Daniel).

With the stage open in more than one tab, only the tab you last clicked or typed in speaks.

Which fixtures are on screen¶

The preview is the app’s 3D map view: each fixture turns slowly, lit with the effect as it runs. Drag one with the mouse to orbit it, scroll to zoom (right-drag or Shift-drag pans); a few seconds after you let go it eases back and turns on its own again. G shows or hides the ground grid and axes.

The live-preview strip shows two fixtures. It starts with the first two that have a map, and follows Claude: when it deploys to one or two fixtures, they come on screen. Ask to see others (“show me the wreath”, “put the arch next to the curtain”) and Claude brings them up; the most recent stay up, and the header says how many fixtures there are in all. A fixture the stage hasn’t deployed to shows its map, dimmed, until an effect is put on it.

Demo mapping¶

Mapping happens in the Splanc app on the phone, so the audience watches it in the phone slot:

  1. In the app, start mapping the fixture and walk through the capture as usual.

  2. When the solve finishes and the map is saved, click Maps on the stage. The preview strip redraws the fixture with its new map.

  3. Ask for an effect that uses the shape, e.g. “a rainbow that climbs from the bottom to the top”. It now follows the real LED positions.

Rehearse first¶

Do one full run at home on the night’s network:

  • Start the stage, check that both fixtures show in the preview strip.

  • Make three or four requests and check that the lights change and the preview matches.

  • Check the mic level: what you say should appear while you’re still speaking. Chrome’s speech recognition needs the internet; Safari’s works offline on recent macOS.

  • Ask one “how does it work?” question and listen to the voice through the room’s speakers; pick a voice you like (see above). Keep the speakers away from the mic.

  • Check the phone mirror, and the clicker if you use one.

  • Watch the cost of the run on console.anthropic.com.

If something goes wrong¶

  • “Claude API: 401”: the key is wrong or not set in this terminal.

  • “Microphone: not-allowed”: allow the microphone for the page (the camera/mic icon in the address bar), then reload.

  • A fixture missing from the preview: ask Claude to show it. If it still doesn’t appear, it isn’t reachable or has no stored map: ask “find the fixtures”, or check it in the app.

  • No voice: click anywhere on the page once (browsers only speak after you’ve interacted with the page), check that Voice is on, and check the Mac’s output device.

  • The preview doesn’t match the lights: the preview runs the same VM on the same map, but isn’t synced to the fixture’s clock, so motion can be out of phase; colours and shapes should match.
